# 决策记录

设计文档 §36 列出 18 项待确认问题。本文件记录**本次实现采用的取值与理由**，
供评审时逐条核对。凡标注「默认」的都是可以低成本调整的实现选择；
标注「需你决定」的会影响业务、成本、身份或权益，上线前必须由你确认。

## 已按设计文档建议落地的默认值

| 编号 | 取值 | 说明 |
| --- | --- | --- |
| D02 | 按真实目录核实，不按名称合并 | 课程身份用 `courses.code` + 目录维护确认；同名不同代码分开（§11.2） |
| D03 | 支持邮箱验证，身份与账号分离 | 邮箱验证不宣称完成官方学生身份认证；`verified_school` 范围在身份方案确定前默认拒绝（§14.1、§15.1） |
| D04 | 公共元数据公开；预览与原件按内容范围 | 由 `AccessPolicy` 三元范围（metadata/preview/original）表达（§15.1） |
| D05 | P1 不接现金，积分规则单独决定 | `COMMERCE_ENABLED=false`；贡献分与真实金额分别记账，积分不构成现金负债（§5.10、§24.1） |
| D06 | PDF、PNG/JPEG、DOCX/PPTX；单文件 50 MiB | `MAX_UPLOAD_SIZE_BYTES` 与 `ALLOWED_UPLOAD_MIME` 单一来源；界面、凭证、网关、后端同值（§16.1） |
| D07 | P1 要求有效预览，异常由管理员处置 | 预览派生失败不改变原件审核事实，但资源不能进入可发布状态（§13.1） |
| D08 | 默认仅公开当前版本 | 历史版本仅作者与有权限管理人员可见（§12.1） |
| D09 | 可撤销会话，不先限制正常多设备学习 | 会话事实在 PostgreSQL，支持按设备撤销（§14.2） |
| D11 | 默认停止新授权、旧链接短期到期 | 下载链接默认 60 秒有效期；文案不承诺"下架后已发链接瞬间失效"（§17.3） |
| D13 | Celery | 任务事实在数据库，Redis 只做投递（§22.1） |
| D14 | 分类制定保留期限 | 具体期限在上线前确认，不在代码中硬编码（§18） |
| D17 | 默认需相应授权 | `AI_ENABLED=false`；开启前需确认未公开资料可否外发模型（§23） |

## 需要你决定（影响业务/成本/身份/权益）

1. **D01 首期范围**：本次按设计文档实现了 P1 主流程，并把 P2 共建能力与 P3/P4 的模块边界一并落地。P3/P4 的接口在开关关闭时返回 `FEATURE_NOT_ENABLED`，不返回假成功（§25.2）。
2. **D10 审核责任主体**：需要指定有限审核人员与目录维护者，否则审核队列无人处理。
3. **D12 存储、邮件与部署服务**：`.env.production` 中为占位项，选定后需验证权限、持久性与成本。
4. **D15 视觉方向与字体**：设计文档 §26.2 给出「纸张或浅色背景、深蓝或墨色文字、有限强调色」，并把具体字体列为待确认；本项目按你既有的跨项目强制规范采用了 **DNDL（DreamNight Design Language）** 的令牌层。两者不完全一致（DNDL 主色为 Teal `#59AAA5`、默认直角）。**这是本实现中最需要你确认的一处**：若课程平台不使用 DNDL，只需替换 `frontend/src/styles/tokens.css` 一个文件，页面代码无需改动。
5. **D16 商业模式、分成与退款**：`COMMERCE_ENABLED=false`。账本、结算与提现的数据模型已按 §24.3 落地，但渠道级状态映射与分成比例需你确定后才能启用。
6. **D18 运维资源与性能目标**：§32 的 P95 指标为建议验收起点，需在实际环境实测确认。

## 与设计文档的已知偏差

1. **专题功能（保研/考研/竞赛/转专业/爬虫）**：§33 要求「不顺手删除专题功能，可暂时隐藏或留待后续评估」。这些功能被迁移到独立模块 `app/modules/topics`，从主导航移除，保留在 `/topics/*` 下并标注为待评估；它们与课程资料主流程不共用模型（§3）。
2. **原 `points` 体系（签到、下载扣分）已移除**：与 §5.10「积分不得自动成为现金负债」和 §24.3「不得用 `users.balance` 直接增减代替账本」冲突。取而代之的是 `creator` 模块的贡献记录。
3. **原 `Download` 表已移除**：替换为 §17.2 的 `DownloadGrant` + `DownloadQuotaUsage`，区分授权、开始与完成（§5.9）。
